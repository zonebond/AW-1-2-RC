# AW 1+2 RC

一个从零实现的格子回合制战棋，玩法取自《Advance Wars》系列，画面走塑料玩具兵人的 3D 风格。

**这不是移植，也不是复刻原版资产。** 单位模型、地形、UI、配色全部是代码程序化生成的，没有使用任何任天堂 / WayForward 的素材。玩法规则（地形消耗、兵种数值、伤害公式）参照系列的公开机制实现。

## 在 macOS 上运行

需要 [Node.js](https://nodejs.org/) 18 以上。

```bash
npm install
npm run dev
```

然后打开终端里输出的地址（默认 http://127.0.0.1:5173/）。

打包成静态站点：

```bash
npm run build     # 输出到 dist/，同时跑一遍类型检查
npm run preview   # 本地预览打包结果
```

## 操作

| 操作 | 说明 |
| --- | --- |
| 左键点自己的单位 | 选中，显示蓝色移动范围和红色可攻击范围 |
| 左键点蓝色格子 | 移动过去，弹出行动菜单 |
| 右键 / `Esc` | 取消。移动后取消会让单位走回原位 |
| 左键点自己的空工厂 | 打开生产菜单 |
| **左键拖动** | 平移镜头（触控板没有中键，所以左键拖动是主要方式） |
| `W` `A` `S` `D` / 方向键 | 平移镜头 |
| **空格** | 镜头重新对准自己的部队 |
| 滚轮 / 触控板双指 | 缩放（开局默认拉近，滚出去可看全图） |
| 中键拖动 | 平移 |
| `E` | 结束回合 |

镜头的平移范围永远被限制在棋盘内：缩放时会重新夹取，所以**不存在把视角推丢、回不来的情况**。真的迷路了，按空格。

选中「攻击」后，鼠标悬停在敌方单位上会显示伤害预测：双方 HP 的变化、对方是否会反击、能否一击击毁。预测按运气值 0 计算，也就是**实际伤害只会等于或高于显示值**。

## 规则要点

- **HP 与伤害**：单位内部 HP 为 0–100，显示为 1–10。伤害公式为
  `(基础伤害 + 运气0~9) × (攻方HP/10) × (100 − 地形星级 × 守方HP) / 100`。
  受伤的单位打得更轻，同时躲在掩体里也更耐打。
- **反击**：只有相邻的直射单位会反击。火炮和火箭炮不反击，也没人能反击它们——这是带间接单位的全部意义。
- **间接单位**：射程大于 1 的单位**移动后不能攻击**，必须提前架好位置。
- **占领**：步兵和机步可占领城市 / 工厂 / 司令部。每回合按自身显示 HP 扣减占领点数，满 20 点易主。占领途中离开或阵亡，进度清零。
- **补给**：停在己方建筑上的单位每回合回复 2 HP（按造价比例扣钱）并补满弹药燃料。
- **胜负**：占领敌方司令部，或全歼敌方单位。

## 兵种

只有陆军。防空导弹车（Missiles）被刻意排除——它是纯对空单位，没有空军的情况下无事可做。

| 单位 | 造价 | 移动 | 移动方式 | 射程 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 步兵 | 1000 | 3 | 步行 | 1 | 可占领 |
| 机步 | 3000 | 2 | 山地靴 | 1 | 可占领，可走山地和河流，反坦克火箭 |
| 侦察车 | 4000 | 8 | 轮胎 | 1 | 视野最广，对步兵有效 |
| 运输车 | 5000 | 6 | 履带 | — | 无武装，可载 1 名步兵 |
| 火炮 | 6000 | 5 | 履带 | 2–3 | 间接 |
| 坦克 | 7000 | 6 | 履带 | 1 | 主力 |
| 防空车 | 8000 | 6 | 履带 | 1 | 对步兵伤害极高 |
| 火箭炮 | 15000 | 5 | 轮胎 | 3–5 | 间接，射程最远 |
| 重坦 | 16000 | 5 | 履带 | 1 | 最强直射 |

## 地图

地图写成两字符一格的文本网格，见 `src/core/map.ts` 的说明。两张内置地图都是 180° 旋转对称的，双方开局条件完全相同。

用 `?map=crossroads` 切换地图。加地图只要在 `src/core/maps.ts` 里加一段字符串和起始单位。

## 代码结构

```
src/core/     规则内核。不引用 three.js，可以独立运行
src/ai/       AI。单回合贪心 + 敌方威胁图
src/render/   three.js 渲染层。程序化几何体、材质、镜头、动画
src/ui/       DOM 界面与交互状态机
tools/        开发工具（见下）
```

`src/core` 与渲染完全解耦，这也是为什么规则可以用无头脚本整局验证。

## 开发工具

```bash
npm test                                    # 规则引擎确定性测试（90 项断言，秒级）
npm run simulate -- twin-bridges 60 12345   # 无头 AI 对 AI 整局对战
npm run playtest -- /tmp/shots              # 真实浏览器操作全流程 + 断言 + 截图
node tools/shot.mjs "URL=>输出路径.png"       # 单张截图
```

测试分两层，各管各的：

- `tools/rules-test.ts` 用固定棋盘和固定运气值断言精确数值——伤害公式、地形消耗、占领节奏、反击规则、胜负条件。规则对不对由它说了算。
- `tools/playtest.mjs` 开真浏览器点界面——选中、移动、取消、占领、生产、攻击预测、AI 回合、重开局。它不断言规则细节，因为一局里能不能占下城市取决于对手怎么打，那不是界面测试该管的事。

调试用 URL 参数：

| 参数 | 说明 |
| --- | --- |
| `?view=units` | 九种兵种双方涂装的近景陈列 |
| `?view=board` | 静态战场，用于看地形和光照 |
| `?view=fx` | 战斗特效实验室，可手动步进时间轴 |
| `?shadow=0\|512\|1024\|2048` | 阴影贴图分辨率，0 为关闭 |
| `?speed=N` | 动画倍速 |
| `?aa=0` | 关闭抗锯齿 |
